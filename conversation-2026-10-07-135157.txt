  The bug I fixed on main (5ea9aed)

  TimeoutExpired wasn't caught anywhere — verified it's a sibling of
  CalledProcessError under SubprocessError, not a subclass, and not an OSError.
  A hung pdftotext would have escaped extract_text and killed the entire state
  run, contradicting the PR's own "never loses a document" promise. Both call
  sites now catch it, with two tests that fail without the fix — I reverted it
  to confirm they're not vacuous.

  Then a bug in my own work, which matters more

  Getting the box ready, the wrapper printed banked so far: 0 for a state with
  86 documents banked. My processed_count looked for scraper/<state>/... under
  SCRAPER_DIR — correct in the stub harness I tested against, wrong in
  production where SCRAPER_DIR is the scraper dir. So the progress guard read
  zero forever, meaning a state making real progress would be declared "stuck" 
  and abandoned — the exact case the guard exists to detect. My test agreed with
  the bug because the stub reproduced the wrapper's logic but not its layout.
  Fixed in 4026a11; the harness now builds the production shape and also covers
  the gave-up branch my first test never reached.

  Two other traps worth knowing: Git Bash wrote the launcher with CRLF, so the
  kernel hunted for an interpreter named /bin/bash\r — I now use git archive or
  strip CRs. And pkill -f run_ocr_priority.sh matched my own ssh command line
  and killed my session, orphaning the python child; I killed it by PID and
  relaunched.
